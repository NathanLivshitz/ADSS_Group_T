## 3. הגדרת מושגים

- **ספק (Supplier)** — גורם חיצוני המספק מוצרים למחסן, בעל ימי הספקה קבועים.
- **כתב כמויות / הסכם הספקה (SupplyAgreement)** — מחיר ליחידה וכמות מינימלית להזמנה אצל ספק מסוים למוצר מסוים; המחיר לכמות נתונה מחושב ע"י `priceFor(quantity)`.
- **הזמנה תקופתית (Order, `orderType = PERIODIC`)** — הזמנה החוזרת ביום קבוע בשבוע.
- **הזמנת חוסר (Order, `orderType = SHORTAGE`)** — הזמנה חד-פעמית המופקת כשמלאי מוצר יורד מתחת לרף.
- **פריט הזמנה (OrderItem)** — מוצר + כמות + מחיר ליחידה בתוך הזמנה.
- **הובלה (Delivery)** — הגעת סחורה מספק, המשובצת למשמרת.
- **מחסנאי / משמרת** — עובד הנדרש להיות נוכח במשמרת בעת קבלת הובלה.

## 4. הנחות

1. כל מוצר מחזיק סף מלאי מינימום (`minLimit`) ישירות במחלקת `Product`.
2. הזמנת חוסר מופקת מהספק הזול ביותר לכמות הנדרשת; שוויון מחירים — נבחר הספק עם מזהה נמוך.
3. עדכון הזמנה תקופתית הוא פעולה אטומית (מחיקת השורות הישנות + יצירת חדשות יחד).
4. מערכת הספקים החיצונית ממומשת באיטרציה זו כמחלקת **mock** (`SupplierController «mock»`) עם ממשק מוסכם — הסכמי הספקה, מועדי הספקה, קבלת ושמירת ההזמנה. המודולים השכנים (עובדים/הובלות) הם באחריות הזוג השכן ונמצאים מחוץ לתחום תרשים המחלקות שלנו.
5. כל ההנחות והתשובות בפורום הקורס מחייבות; סתירות מול הפורום ייבחנו לפני הגשה.

## 5. עיצוב ותרשימים (סעיף 3.1)

- **תרשים המחלקות המאוחד** (`3.1-class-diagram/class_diagram_combined`) הוא **Design Class Diagram שכבתי** של שני המודולים של הזוג (מלאי + ספקים) יחד: Presentation → Service → Domain (Controller + ישויות) → «interface» Repository, עם רצועת **Supplier Integration — Mock** המייצגת את מערכת הספקים החיצונית (`SupplierController «mock»` + `Supplier` / `SupplyAgreement` / `DeliverySchedule` / `SupplierOffer`).
- **התאמה לחוזים ולתרשימי הרצף (סעיפים 2.1–2.2):** המחלקות והמתודות בתרשים המחלקות תואמות אחד-לאחד לחוזים ולתרשימי הרצף של ניר. לדוגמה, תרחיש החוסר (UC f):
  `InventoryService.orderShortageFromSupplier()` → `InventoryController.getLowStockProducts()` → `getProducts()` → לולאה על `Product.getTotalQuantity()` / `Product.getMinStockThreshold()`; ואז `selectProduct(productId)` → `SupplierService.createOrderProposal(...)` → `SupplierController.findAgreements(...)` → `SupplyAgreement.priceFor(qty)` → בחירת הספק הזול → `OrderProposal.create(...)`; ולבסוף `confirmOrder(orderProposalId)` → `Order.create(orderProposal)` → `SupplierController.registerAndTransmitOrder(...)` → `Supplier.receiveOrder(...)` → `InventoryController.updateShortageReport(...)`.
- **תבנית שכבת הנתונים** (NF-2/NF-3) עוקבת אחר מאגר הייחוס שהוצג בתרגול: **`https://github.com/Maximbrg/stock-app-repo-dao-v2`** —
  `presentation/InventoryMenu` · `service/{ServiceController + השירותים}` · `domain/{InventoryController, ישויות, «interface» Repository}` · `dataaccess/dao/{XDAO + JdbcXDAO}` · `dto/XDTO` · `DatabaseManager → SQLite`.
  כדי לשמור על קריאוּת, **תרשים המחלקות מציג את ממשקי ה-Repository בלבד**, ואילו פירוט ה-RepositoryImpl/DAO/JdbcDAO/DTO מופיע בתרשים הארכיטקטורה הייעודי (`3.1-class-diagram/data_layer_architecture`).
