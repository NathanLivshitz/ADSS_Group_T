# מטלה 2 — סעיף 2.1: חוזי פעולות מערכת (Contracts)

> תבנית מבוססת **Practice 7 — Larman Development Process, slide 9** של הקורס.
> כל חוזה כולל 4 חלקים: Operation / Cross References / Preconditions / Postconditions.
> Postconditions בלשון עבר ("X was created", "Y was associated with Z") — לא בלשון ציווי.

תרחיש השימוש שנבחר לפירוט: **UC f — הוצאת הזמנה מספק עקב חוסר**.
שלוש פעולות המערכת תואמות אחת-לאחת לשלושת תרשימי הרצף (סעיף 2.2) ולתרשים המחלקות (`class_diagram_combined`).

---

## הנחות עבודה (מודל מתואם עם תרשים המחלקות)

**ישויות מצד המלאי (שלנו):**
- `Product` — מוצר (productID, shopQuantity, warehouseQuantity, `minLimit`, costPrice, sellPrice, …); חושף `getTotalQuantity()` ו-`getMinStockThreshold()`.
- `Order` — הזמנה (orderId, supplierId, items : List<OrderItem>, status : OrderStatus, orderType : OrderType, …).
- `OrderItem` — פריט הזמנה (product, quantity, unitPrice).
- `OrderProposal` — סיכום הזמנה לאישור (productId, requiredQty, supplierId, price).

**ישויות מצד הספקים (mock — מערכת חיצונית):**
- `SupplierController «mock»` — גבול מערכת הספקים (findAgreements, registerProposal, registerAndTransmitOrder, …).
- `Supplier` — ספק (supplierID, supplierName); מקבל הזמנה ב-`receiveOrder(o)`.
- `SupplyAgreement` — הסכם הספקה / כתב כמויות (productId, minQuantity, unitPrice); מחיר לכמות מחושב ב-`priceFor(quantity)`.

## Contract C1: `orderShortageFromSupplier`

**Operation:**
`orderShortageFromSupplier()`

**Cross References:**
Use Case f — הוצאת הזמנה מספק עקב חוסר (שלב 1: חישוב והצגת דוח החוסרים)

**Preconditions:**
- עובד המחסן מחובר למערכת ומורשה להוציא הזמנות.
- נתוני הפריטים קיימים במערכת, כולל כמויות המלאי (`shopQuantity` + `warehouseQuantity`) ורמת המינימום (`minLimit`) של כל פריט.

**Postconditions:**
- דוח החוסרים was computed and displayed to the warehouse worker — לכל `Product` שבו `getTotalQuantity() < getMinStockThreshold()` *(no state change — query/report step)*.
- הדוח כלל עבור כל פריט: פרטי הפריט, הכמות הקיימת ורמת המינימום.
- אם אין פריטים בחוסר — הדוח ריק והוצגה הודעה מתאימה ("No products below minimum stock level").
- **No `Order` was created** at this step *(read-only operation)*.

---

## Contract C2: `selectProduct`

**Operation:**
`selectProduct(productId : String)`

**Cross References:**
Use Case f — הוצאת הזמנה מספק עקב חוסר (שלב 3: בחירת פריט, בחירת ספק ובניית סיכום הזמנה)

**Preconditions:**
- דוח החוסרים חושב והוצג לעובד המחסן (ראו C1).
- הפריט (`productId`) קיים ברשימת החוסרים שבדוח.

**Postconditions:**
- כל הספקים המספקים את הפריט were located מתוך הסכמי ההספקה (`SupplierController.findAgreements(productId)` → קבוצת `SupplyAgreement`) *(query step)*.
- `requiredQty` was computed כך שרמת המלאי הצפויה לאחר קבלת ההזמנה תהיה גבוהה מ-`minLimit` (`requiredQty = minThreshold − currentQty + 1`).
- For each `SupplyAgreement`: מחיר ההזמנה was computed לפי `priceFor(requiredQty)` (כתב הכמויות של הספק).
- הספק בעל המחיר המשתלם ביותר was selected — by comparing every supplier's `priceFor(requiredQty)` and choosing the minimum *(selection step — no state change)*.
- An `OrderProposal` instance was created *(instance creation)* — `productId`, `requiredQty`, `supplierId` (הספק שנבחר) ו-`price` were set *(attribute modification)*.
- ה-`OrderProposal` was registered ב-`SupplierController` *(association formed)* וקיבל `orderProposalId`.
- סיכום ההזמנה was displayed לעובד המחסן לאישור.

---

## Contract C3: `confirmOrder`

**Operation:**
`confirmOrder(orderProposalId : String)`

**Cross References:**
Use Case f — הוצאת הזמנה מספק עקב חוסר (שלב 9: אישור ההזמנה, יצירתה ושליחתה לספק)

**Preconditions:**
- סיכום הזמנה (`OrderProposal` עם `orderProposalId`) הוצג לעובד המחסן וכולל פרטי פריט, כמות נדרשת, ספק שנבחר ומחיר.
- עובד המחסן אישר את ההזמנה.

**Postconditions:**
- An `Order` instance was created with a unique `orderId` *(instance creation)* — מפרטי ה-`OrderProposal` (`getDetails()`).
- An `OrderItem` was created and associated with the `Order` *(instance creation + association formed)* — `quantity = requiredQty`, `unitPrice = price`.
- ה-`Order` was associated with the selected `Supplier` *(association formed)*; `status` was set to `SENT` ו-`orderType` to `SHORTAGE` *(attribute modification)*.
- ההזמנה was transmitted and recorded במערכת הספקים (`SupplierController.registerAndTransmitOrder` → `Supplier.receiveOrder`).
- הפריט was marked as "ordered" בדוח החוסרים (`InventoryController.updateShortageReport(productId, ordered)`) *(attribute modification)*.
- פרטי המלאי של הפריט (`shopQuantity` / `warehouseQuantity`) were **not** updated at this step — עדכון המלאי מתבצע רק עם קבלת ההזמנה בפועל (`status = RECEIVED`).

## הערות חשובות לבוחן/לקבוצה

1. **שלוש פעולות מערכת = שלושה שלבים ב-UC f** — חישוב הדוח (`orderShortageFromSupplier`), בחירת פריט ובניית הצעה (`selectProduct`), ואישור ההזמנה (`confirmOrder`). כל אחת מופעלת ע"י עובד המחסן ויוצרת/משנה state — לכן היא system operation לפי Practice 7.
2. **בחירת ספק זול ביותר ב-C2** — הלוגיקה הקריטית של תרחיש f. השווינו לכל הסכם הספקה את `priceFor(requiredQty)` (כתב הכמויות) ובחרנו את המינימום. עומד בדרישה SUP-7.
3. **הגנת `minLimit`** — ב-C2 חישוב `requiredQty` מבטיח שרמת המלאי הצפויה עם קבלת ההזמנה תעלה על המינימום (דרישה SUP-8).
4. **הפרדת "הזמנה" מ-"קבלת הזמנה"** — ב-C3 ההזמנה נשמרת ונשלחת לספק והפריט מסומן "הוזמן", אך **מלאי המוצר אינו מתעדכן** עד קבלת הסחורה בפועל (דרישה SUP-9). זו הסיבה שאין postcondition שמשנה את `shopQuantity`/`warehouseQuantity` ב-C3.
5. **למה אין selection logic ב-postconditions בלשון state-change?** — איתור הספקים ובחירת הזול הם חישוב לקריטריון, לא שינוי state; סומנו במפורש כ-query/selection steps. שינויי ה-state מתחילים ביצירת ה-`OrderProposal` (C2) וה-`Order` (C3).
6. **תאימות לתבנית BGU** — כל ה-postconditions בלשון עבר ("was created", "was associated", "was set"), מחלקות ב-CamelCase, פעולות ב-camelCase. עומד בפורמט slide 9.

## סעיף 2.2 — תרשימי רצף (קיימים)

לכל אחד משלושת החוזים קיים תרשים רצף תואם:
- C1 → `sequence-orderShortageFromSupplier` — `InventoryService` → `InventoryController.getLowStockProducts()` → לולאה על `Product`.
- C2 → `sequence-selectProduct` — `InventoryService` → `SupplierService.createOrderProposal()` → `SupplierController.findAgreements()` → לולאה על `SupplyAgreement.priceFor()` → בחירת המינימום → `OrderProposal.create()`.
- C3 → `sequence-confirmOrder` — `InventoryService` → `SupplierService.createOrder()` → `Order.create()` → `SupplierController.registerAndTransmitOrder()` → `Supplier.receiveOrder()` → `InventoryController.updateShortageReport()`.
